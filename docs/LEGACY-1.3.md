# MFG Enabler 1.3

RTX 30 시리즈용 DLSSG Native 설치·복구 도구. Windows x64 데스크톱 앱이며, 게임마다 **MFG 활성화**와 선택 사항인 **RTX 5080 인식**을 각각 체크해 설치·해제합니다. 관리 프로그램의 소스는 GNU GPL version 3 라이선스로 공개·빌드할 수 있습니다.

## 실행

1. `MFG-Enabler.exe` 실행(빌드 출력은 `dist/MFG-Enabler.exe`). Windows 10/11 x64, .NET Framework 4.8 환경을 권장합니다.
2. **NVIDIA App 열기**로 NVIDIA App에서 게임 검색을 실행한 뒤, 이 도구의 **NVIDIA 목록 새로고침**을 누릅니다. 시작 시에도 NVIDIA의 저장된 검색 결과를 자동으로 읽습니다.
3. FG 후보 목록에서 게임과 **NVIDIA 감지 실행 파일**을 확인합니다. NVIDIA의 `DriverProfile`에 있는 실행 파일을 우선 선택합니다. 경로가 모호하면 NVIDIA가 기록한 후보 중 실제 렌더링 EXE를 선택해야 합니다.
4. 게임을 종료하고 **MFG 활성화**를 체크합니다. 현재 선택된 SM86 패키지에서 프록시와 INI를 내려받아 해시 확인 후 설치합니다.
5. 게임을 시작하고 게임 설정에서 DLSS 프레임 생성과 지원 배율을 선택합니다.
6. GPU 식별을 바꾸려면 **RTX 5080 인식 (선택)**도 체크합니다. 각 체크 해제는 해당 기능만 복구하며, **전체 복구 / 해제**는 두 기능을 모두 복구합니다. 게임을 종료한 뒤 사용하세요.

첫 다운로드에는 인터넷이 필요합니다. 이후 같은 버전은 검증된 로컬 캐시를 사용합니다. 보호된 게임 폴더의 접근이 거부되면 앱을 종료하고 관리자 권한으로 실행할 수 있습니다. 관리자 권한은 자동 요청하지 않습니다.

## SM86 자동 업데이트

**SM86 자동 업데이트**를 켜면 설정이 저장되고 실행당 한 번 최신 커밋을 확인합니다. 기본값은 꺼짐입니다. 실행 중 처음 켤 때도 한 번 확인하며, 껐다 다시 켜도 같은 실행에서는 중복 확인하지 않습니다.

새 버전이 있으면 공식 저장소의 변경 불가능한 커밋 주소에서 5종 프록시와 INI를 받아 Git blob 해시와 SHA-256을 확인하고 현재 패키지를 전환합니다. 앱 재빌드는 필요 없습니다. 문서만 바뀌고 런타임 파일과 버전이 동일하면 패키지를 다시 받지 않습니다.

이미 이 도구로 MFG를 적용한 게임은 자동 갱신합니다. 실행 중, 접근 거부, 외부 파일 변경, 중단된 작업 상태는 건너뛰며 다음 실행에서 다시 시도합니다. 아직 MFG를 적용하지 않은 게임을 새로 활성화하지 않습니다. 최초 원본 백업은 유지하고, 5080 인식 프록시는 업데이트 대상에서 제외합니다. 업데이트 도중 오류가 나면 이전 설치 버전으로 되돌리기를 시도하며, 강제 종료 뒤에는 전체 복구로 최초 상태를 복원할 수 있습니다.

체크박스 아래의 버전 표시를 누르면 보류·실패 이유를 볼 수 있습니다. GitHub 연결 실패나 다운로드 오류 시 기존 패키지를 유지합니다. NVIDIA 검색 실패로 복구 전용이 된 게임도 기존 관리 기록이 있으면 업데이트 대상이 될 수 있습니다.

자동 업데이트 대상은 **SM86 런타임**입니다. 앱 자체와 5080 프록시를 내려받아 실행하는 기능은 아닙니다. upstream의 파일명, 기본 SM86/PTX 구성 또는 버전 표기 형식이 바뀌면 자동 적용을 중단합니다. 그처럼 설치 방식 자체가 바뀐 경우에는 앱 수정이 필요할 수 있습니다.

## RTX 5080 인식 (선택)

FakeNvAPI의 GPU 식별 응답 방식을 참고한 독립 NVAPI 프록시입니다. 기본값은 미적용입니다. 게임 폴더에 `nvapi64.dll`을 설치하고, 기존 파일이 있으면 별도 백업한 뒤 해제 시 복원합니다. 다른 NVAPI 모드가 있으면 이 옵션이 적용된 동안 기존 파일 대신 사용됩니다.

이 프록시를 로드한 게임에서 RTX 30의 NVAPI 이름·PCI ID·아키텍처 응답을 RTX 5080으로 바꿉니다. 나머지 NVAPI 호출은 시스템 NVIDIA 드라이버에 전달합니다. Windows의 GPU 이름, DXGI 어댑터 정보, 실제 GPU 성능·VRAM·CUDA 능력은 바꾸지 않습니다. 게임이 시스템 NVAPI를 절대 경로로 로드하거나 다른 API로 GPU를 판정하면 메뉴 해금 효과가 없을 수 있습니다. 실제 FG 지원이 없는 게임에 FG 기능을 추가하지도 않습니다.

MFG만 사용하려면 첫 체크만 켜고, 두 기능을 사용하려면 둘 다 켜세요. 각 기능은 독립적이므로 MFG 체크만 해제하면 5080 인식은 남습니다. [구현 범위와 참고 자료](docs/SPOOF5080.md)를 확인할 수 있습니다.

## NVIDIA App 기반 게임 감지

1.1에서는 **Steam/Epic/GOG 자체 탐색 및 임의 EXE 추가를 제거**했습니다. NVIDIA App이 검색한 설치 목록을 직접 가져오는 방식입니다. NVIDIA App 설치와 해당 Windows 사용자 계정의 검색 결과가 필요합니다. 첨부된 프로그램 파일만 복사해 놓는 것으로는 설치 목록이 생성되지 않습니다.

다음 데이터를 읽기 전용으로 사용합니다.

- `%LOCALAPPDATA%/NVIDIA Corporation/NVIDIA App/NvBackend/ApplicationStorage.json`: 게임 이름, 설치 폴더, 감지 파일, 드라이버 프로필, fingerprint 감지 여부, FG 차단 플래그.
- NVIDIA App의 `ApplicationOntology/data/fingerprint.db`: XML 프로필입니다. CMS ID, 짧은 이름, 버전이 모두 일치하는 경우에만 실행 경로와 누락된 차단 정보를 보완합니다. 사용자 캐시를 우선하고 없으면 설치 폴더를 확인합니다.

NVIDIA fingerprint로 확인된 항목 중 FG override 차단이 없고, 설치 폴더에서 x64 `nvngx_dlssg.dll`을 찾은 게임만 FG 후보로 표시합니다. `nvngx_dlss.dll`(초해상도)만 있거나, 단순 수동 등록, 크리에이티브 앱, 제거된 설치, 정보가 없는 항목은 제외합니다. 전체 드라이브나 스토어를 다시 검색하지 않습니다. FG 파일은 NVIDIA가 지정한 설치 폴더 안에서 최대 12단계까지 확인하며 정션과 `.mfg-enabler`는 건너뜁니다.

**FG 차단 플래그가 꺼져 있다는 것만으로 FG 지원을 확정하지 않습니다.** NVIDIA 목록과 DLL의 존재를 함께 확인하는 보수적 후보 필터입니다. DLL이 실제 실행 중 로드되는지, 해당 게임 모드에서 D3D12/FG를 사용하는지, 3X/4X를 요청할 수 있는지는 정적 검사로 보장하지 않습니다. 특수한 패키징의 지원 게임이 누락될 수도 있습니다. GPU의 공식 FG 지원 여부로 RTX 30을 제외하지 않습니다.

**감지 상세**에서 데이터 갱신 시각, 읽은 파일, 제외 사유를 확인할 수 있습니다. 목록이 비어 있으면 NVIDIA App의 검색 위치와 검색 결과를 먼저 확인하세요. 새로고침 버튼은 저장된 결과를 다시 읽으며 NVIDIA App 내부 스캔을 원격으로 실행하지 않습니다. 데이터가 없거나 형식이 달라지면 오류를 표시하며 이전 스토어 탐색으로 우회하지 않습니다. 활성화 직전에도 NVIDIA 기록과 FG 파일을 재확인합니다.

기존 버전의 일반 검색 항목은 정리합니다. 이미 적용된 게임이 NVIDIA 후보에서 빠진 경우에는 **복구 전용**으로 남겨 체크 해제·복구를 허용합니다. 이 항목에서는 새로 활성화할 수 없습니다. NVIDIA App이 실행 중이지 않아도 유효한 검색 결과가 있으면 읽을 수 있습니다.

## 정확히 무엇을 설치하나요?

[sdli1995/dlssg_for_sm86](https://github.com/sdli1995/dlssg_for_sm86)의 **DLSSG Native 0.2.4**를 기본 버전으로 사용합니다. 기본 커밋은 `5f62ff44a9c08f9841fa605e7b7160f79ccd2c40`이며, 자동 업데이트로 이후 버전을 받을 수 있습니다.

- 렌더링 EXE 옆에 `version.dll`과 `dlssg_sm86.ini`를 설치합니다. 대체 프록시 `winmm.dll`, `dinput8.dll`, `winhttp.dll`, `dxgi.dll`도 선택할 수 있습니다. 게임이 해당 프록시를 로드해야 작동합니다.
- 게임의 `nvngx_dlssg.dll`은 수정하지 않습니다. 별도 모드 관리 프로그램은 필요 없지만, 설치하는 DLSSG Native 자체는 프록시/hook 방식의 비공식 모드입니다. NVIDIA 공식 RTX 30 MFG 지원을 켜는 도구는 아닙니다.
- 기본 구성은 SM86 / PTX, 정확 샘플링, 최대 추가 3프레임입니다. 4X를 강제로 요청하지 않습니다. 실제 배율과 호환성은 게임에 달려 있습니다.
- **적용됨**은 설치 파일의 해시 일치를 의미합니다. 실제 GPU 출력이나 프레임 생성 성공을 감지하는 기능은 아닙니다.
- upstream의 현재 범위는 Windows x64 / D3D12입니다. Vulkan 및 모든 게임의 동작을 보장하지 않습니다. 안티치트가 있는 게임은 해당 게임의 모드 정책을 확인하세요.

## 원본 보존과 복구

기존 프록시와 이름이 충돌하면 덮어쓰지 않습니다. 다른 프록시를 선택할 수 있지만 다른 모드와의 공존을 보장하지는 않습니다. 동일 버전의 수동 설치 프록시는 중복 설치를 거부합니다. 오래된 수동 설치 버전은 자동 식별하지 않으므로 upstream 안내대로 먼저 정리해야 합니다.

기존 INI는 실행 파일 옆 `.mfg-enabler`에 고유 백업으로 보관합니다. 기록을 먼저 디스크에 저장하고 파일을 교체하여 중단된 작업도 복구할 수 있습니다. 해제 시 원래 없었던 파일은 삭제하고, 원래 있던 INI는 SHA-256 검증 후 복원합니다. 이 도구가 적용하기 전 상태로 돌아가며, 기존에 설치된 다른 모드까지 제거하지는 않습니다.

외부에서 변경된 DLL/INI는 자동 덮어쓰기·삭제하지 않습니다. 변경된 파일을 다른 폴더로 이동한 뒤 복구 버튼을 누르세요. 백업 손상 시에는 복구를 중단합니다. 게임 업데이트 뒤에도 같은 확인이 적용됩니다.

복구 기록과 백업 폴더는 해제 후에도 보존합니다. upstream이 실행 중 생성한 `dlssg_sm86/logs` 등 런타임 파일은 자동 삭제하지 않습니다. 백업을 지우면 이전 상태 복원이 불가능하므로 적용 중 `.mfg-enabler`를 삭제하지 마세요. 게임 폴더 이동 시에는 먼저 해제하고 NVIDIA App에서 새 위치를 다시 검색하세요.

실행 중 프로세스의 경로를 확인하지만 Windows 권한 때문에 일부 프로세스는 읽지 못할 수 있습니다. 게임을 직접 완전히 종료한 뒤 작업하세요. 정션·심볼릭 링크 경로는 지원하지 않습니다.

게임 목록: `%LOCALAPPDATA%/MFG Enabler/games.json`  
다운로드 캐시: `%LOCALAPPDATA%/MFG Enabler/payload/<commit>/`

## 소스 빌드

Windows PowerShell에서 프로젝트 루트 기준:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

출력은 `dist/MFG-Enabler.exe` 하나입니다. ZIP 패키지는 만들지 않습니다. 소스는 `src/`와 빌드 스크립트로 제공됩니다.

C# 부분은 Windows .NET Framework 컴파일러를 사용합니다. `build-native.ps1`은 첫 빌드 때 공식 Zig 0.15.2 도구 모음(약 93 MB)을 다운로드하고 고정 SHA-256 확인 후 `.cache/toolchains`에 보관합니다. 해당 컴파일러로 `src/native/nvapi_proxy.c`를 빌드해 EXE에 포함합니다. Visual Studio나 NuGet은 필요 없습니다. 첫 소스 빌드에는 인터넷이 필요하며 사용자 실행에는 Zig가 필요 없습니다.

기능 테스트와 게임 실행 확인은 사용자 담당입니다. 이번 버전은 구현과 EXE 빌드까지 수행했습니다. 기존 테스트 소스와 `test.ps1`은 필요하면 직접 사용할 수 있지만 빌드 스크립트에서 테스트를 실행하지 않습니다.

`src/payload.lock`은 기본 SM86 파일의 이름, 상대 경로, SHA-256, Git blob SHA-1을 보관합니다. 이후 버전은 실행 시 공식 저장소의 메타데이터를 읽어 처리합니다. 해시는 파일 동일성 확인이며 코드 안전성을 증명하지는 않습니다.

## NVIDIA App 참고 범위 / 라이선스

NVIDIA App 11.0.9.251의 제공된 프로그램 폴더와 로컬 검색 캐시 구조를 확인했습니다. 이 도구는 NVIDIA가 이미 수행한 탐색 결과를 읽는 독립 C# 구현입니다. 비공개 네이티브 스캐너를 복사하거나 내부 RPC를 호출하지 않습니다. NVIDIA의 코드·이미지·로고·EXE·fingerprint DB는 배포물에 포함하지 않습니다. 캐시 형식은 NVIDIA 업데이트에 따라 달라질 수 있습니다. [연동 확인 사항](docs/NVIDIA-INTEGRATION.md)을 참고하세요.

관리 프로그램과 독립 NVAPI 프록시 소스는 GNU GPL version 3 라이선스입니다. upstream의 DLL·모델·커널은 별도 제3자 자료이며 이 프로젝트의 GPL로 재라이선스하지 않습니다. SM86 DLL은 EXE에 포함하지 않고 사용자 실행 시 upstream에서 받습니다. 독립 구현한 5080 NVAPI 프록시는 소스와 함께 제공하고 EXE에 포함합니다. [upstream 고지](docs/UPSTREAM-NOTICES.txt)를 함께 제공합니다. upstream 런타임 자체를 소스로 재빌드하는 프로젝트는 아닙니다.
